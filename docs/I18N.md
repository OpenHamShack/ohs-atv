# Strings and languages

OpenHamShack ATV ships in English for the beta, but no user-visible text
belongs in code: it goes through Qt's translation mechanism, with English as
the source language, so another language is a catalog away. The family-wide
rule is `~/openhamshack/docs/contract/I18N.md`; this page is how it works here.

## Adding a string

Write the English inside `self.tr()` in any `QObject` subclass (every widget,
window and dialog), or `QCoreApplication.translate("Context", "...")`
elsewhere:

```python
self.setWindowTitle(self.tr("OpenHamShack ATV"))
self.rec_btn.set_text(self.tr("Recording {seconds} s").format(seconds=...))
self.picture_card.set_title(self.tr("Teletext · %n page(s) received", "", n))
```

- **Whole sentences, named placeholders.** `{seconds}` filled by `.format()`
  after `tr()`, never `"Recording " + n + " s"`: other languages put the
  number elsewhere.
- **Plurals through `%n`**, never `'s' if n != 1`. Write the English as
  `page(s)`: `tools/i18n.py extract` writes the two English forms ("page",
  "pages") into the catalog from that. A plural the convention cannot spell
  ("entry/entries") has its forms written into the `.ts` by hand once, and
  the check says which.
- **Not translated:** callsigns, locators, teletext page numbers, system
  names used as identifiers, file names, key sequences (`QKeySequence("Ctrl+S")`
  stays as written; Qt shows it in the user's language). **The transmitted
  picture is not UI:** the ident, test card and teletext pages that go on air
  are what the station sends, not words for the operator, and stay as the
  operator wrote them.
- **Frequencies** through `ohsatv.i18n.fmt.frequency(hz, unit, decimals)`:
  kHz below 30 MHz, MHz above (or the unit the field fixes), the locale's
  decimal separator, never grouped. The monitor's caption pill uses it. Not
  the top bar's readout, whose digits are edited one by one; not file names
  (snapshot PNGs keep `1275.000MHz`); not the radio lock's notes, which other
  programs read.
- **Other numbers beside a unit** (MS/s, an axis in MHz, dB, %) through
  `fmt.number(value, decimals)`: the same separator and no grouping; `None`
  decimals is the shortest form, as `:g` was. The Teletext editor (`ohstxt/`)
  has its own catalog, `ohstxt/i18n/fmt.py` with the same two helpers, and
  its own `tr()` contexts.
- **Subclasses:** PyQt's `self.tr()` looks strings up under the class of the
  object, not the class whose code called it. A string in a base class whose
  subclasses are what get built (`Card`, under `TransmitPanel`, `PlanCard`
  and `BandCard`) needs `QCoreApplication.translate("Card", ...)`.
- **A name that is also a key** keeps its English as the key and translates
  only what is drawn: `SettingsDialog.PAGES` is looked up by "Station",
  "Radio"... (by `_page` and the tests), and `page_names()` gives what the
  navigation shows.

Then refresh the catalog (below) and commit the `.ts` and `.qm` with the code.

## Sentences no widget says: gettext

What the engine and the store form's server say without a widget (the
`--server` API's errors and status words now; the engine's toasts and
refusals as M3 converts them) is not a Qt string: those run without Qt
(`--headless`, `--server`, a store container with no PyQt), so they go
through gettext, in the domain `ohsatv` (`ohsatv/i18n/text.py`):

```python
from ohsatv.i18n.text import _, ngettext

raise ValueError(_("{keys}: the controller looks after these").format(keys=keys))
```

The same rules as Qt's: whole sentences, `{name}` placeholders filled by
`.format()` after `_()`, never an f-string inside it (the template would
hold the f-string's source, which nothing looks up), plurals through
`ngettext`, `pgettext` where one English word means two things.

The English template, `ohsatv/i18n/ohsatv.pot`, is written by `tools/i18n.py
pot` and committed; `tests/test_i18n.py` runs `tools/i18n.py pot --check`,
and shack-i18n-check checks each call's msgid against it. Translations will
go under `ohsatv/i18n/locale/<lang>/LC_MESSAGES/ohsatv.mo`; English needs none.

## Regenerating the catalogs

```
tools/i18n.py extract     # pylupdate6 refreshes ohsatv/i18n/ohsatv_en.ts and ohstxt/i18n/ohstxt_en.ts, then compiles the .qm
tools/i18n.py compile     # .ts -> .qm only, after editing a .ts by hand
tools/i18n.py pot         # the gettext template, from the _()/ngettext()/pgettext() calls
```

`extract` needs `pylupdate6`, which comes with pip's PyQt6 but not with
Debian's. Once per machine:

```
python3 -m venv --system-site-packages ~/build/venvs/ohs-qt
~/build/venvs/ohs-qt/bin/pip install PyQt6
PYLUPDATE6=~/build/venvs/ohs-qt/bin/pylupdate6 tools/i18n.py extract
```

The `.qm` is compiled by `tools/i18n.py` itself (byte for byte what Qt's
`lrelease` writes), and committed: the .deb copies `ohsatv/` as it is and the
Windows spec takes every non-Python file under `ohsatv/`, so the catalog ships
without a packaging change. The English catalog is loaded even in English,
because it carries the English plural forms.

**Which language:** `SHACK_LOCALE` (for example `de`, `pt_BR`, `en-XA`) if
set, otherwise the desktop's preferred languages; a language without a
catalog falls through to English. `tools/i18n.py pseudo` writes the en-XA
pseudo-locale (accented, 40% longer, bracketed) beside the English catalog,
so `SHACK_LOCALE=en-XA python3 -m ohsatv` shows at a glance any string that
escaped `tr()` and any label that clips. Do not commit those files.

## The check and the baseline

`tools/i18n.py check` runs ohs-libs' `shack-i18n-check` (vendored as a pinned
wheel in `tools/vendor/`), and `tests/test_i18n.py` runs it in every suite run,
so it fails the tests. It finds user-visible literals passed to Qt's text
APIs and to this app's own widgets and helpers (the sink list in
`.i18n-check.toml`, which also says what was left out and why), and checks
that every string the code asks for is in the English catalog.

- **`i18n-pending.txt` is the baseline**: the literals that were already in
  the code when the check arrived (ATV's and the Teletext editor's). M3
  emptied it on 9 October 2026; it stays, empty, and anything new fails. The
  last line of the check's output (also printed in the test run) gives the
  count, and M3 drives it to zero. Converting a literal leaves its baseline
  line matching nothing, which fails until `tools/i18n.py baseline` removes
  it, so the count only falls. `baseline` never adds lines; `--add-new` was
  for writing it the first time.
- **`i18n-allow.txt` is for literals that are not language**, each with a
  reason: unit symbols drawn alone, on-air content, the editor's key
  sequences, the live runner's log lines, a protocol token. An entry that stops matching fails the check.
- A new widget that shows a text argument goes into the sink list, so the
  check sees it.
- **Not seen by the check, and M3's all the same:** text in tables rather
  than at a call (settings.py's `LABELS` and `CHOICE_LABELS`, chrome.py's
  shortcut list, the strings a function returns for a caller to draw), and
  the engine's sentences (state.py's setting help, bands.py's notes and
  refusals, device errors), which belong in a gettext domain in the engine.
